# Dialogue Protocol

## 1. 1ターンの構造

各レビュー応答の冒頭で、直前ステージ、現在ステージ、全9ステージ中の位置を必ず表示する。直前ステージはパイプライン順で現在ステージの1つ前を指す。S1では「なし」、S9完了時も現在ステージはS9、進捗は `9/9` とする。

```markdown
### 現在地
| 項目 | 状態 |
|---|---|
| 直前ステージ | Target Value Loop（S3） |
| 現在ステージ | Decision Specification（S4） |
| 進捗 | 4/9 |
| Blocking | 1 |
| 仮定 | 2 |

### 今決めること
（質問は1つ）

| 案 | 効果 | 欠点 | 関連原則 |
|---|---|---|---|

**推奨：案X**
理由：...

**回答：** 案Xなら `y`、案Yなら `n` と答えてください。
```

現在地のユーザー向け応答には、次を必ず含める。

| 項目 | 契約 |
|---|---|
| 直前ステージ | パイプライン上で現在ステージの1つ前。S1では「なし」 |
| 現在ステージ | ステージ名と `S1`〜`S9` のID |
| 進捗 | 現在ステージの位置を分子、固定値9を分母にした `n/9`。承認済み件数ではない |

完全なステージ一覧を併記する場合も、この3項目は省略しない。Blocking中は停止しているステージを現在ステージとして表示する。上流へ戻った場合は、戻った先を現在ステージとして位置を再計算する。

質問データとユーザー向け応答には、次を必ず含める。

| 項目 | 契約 |
|---|---|
| `answer_type` | `yes_no`、`single_choice`、`free_text` のいずれか |
| `recommended_answer` | `yes_no` は `y` / `n`、`single_choice` は選択肢ID。`free_text` だけ空を許可 |
| `recommendation_reason` | 推奨理由を1〜2文。`free_text` で推奨保留なら不足証拠を書く |
| `answer_guide` | 許容する回答と各回答の意味。`yes_no` は `y` と `n` の両方を示す |

既知情報から選択肢を安全に導ける場合は `yes_no` または `single_choice` を優先する。根拠なく選択肢を作ることになる場合だけ `free_text` を使い、ユーザー向けには **推奨：保留** と明示する。

## 2. 質問の選定

まず質問候補を次の階層へ分類する。最上位の未解決階層を選んでから、その階層内だけでスコアを比較する。異なる階層間で点数を比較しない。

| 優先度 | 分類 | 条件 |
|---:|---|---|
| 1 | safety_blocking | 放置するとデータ損失・不可逆な費用発生・権限違反・機密漏えいが起きる |
| 2 | normal_core | S1では現行業務の正常系を理解し、S3以降では目標の価値獲得までを成立させる |
| 3 | normal_friction | 正常系の理解、判断負荷、待ち時間、フィードバックを決める |
| 4 | exception | 準正常系、異常系、低頻度エラー、回復経路を決める |

優先度1がなければ、現在ステージの正常系が確定するまで優先度4を `deferred` にする。S1の業務理解が未承認ならS3の目標価値ループを質問しない。単なる実装失敗や低頻度の例外を safety_blocking に分類しない。

選択した階層内で次を加点する。

| 項目 | 点 |
|---|---:|
| 複数の下位判断を同時に決める | +40 |
| 現在ステージのゲートを開く | +20 |
| 高い不確実性を解消する | +10 |
| 既に回答済み | -1000 |
| 見た目だけ | -20 |

最大スコアの質問を1問だけ返す。同点なら、価値獲得までの時系列で早い論点を選ぶ。

## 3. 質問タイプ

| 種類 | 形式 |
|---|---|
| 優先順位 | AとBが衝突しています。どちらを優先しますか |
| 責任分担 | この判断はユーザー・システム・専門家の誰が担いますか |
| 条件境界 | どの条件からAではなくBになりますか |
| 例外 | 通常ルールが適用できないケースはありますか |
| 可逆性 | 後から戻せますか。戻せるなら今決める必要がありますか |
| 成功条件 | 何ができれば設計成功とみなしますか |

## 4. 回答処理

回答を受けたら：

1. 事実／決定／仮定のどれかに分類
2. 決定ログへ追加
3. Decision RequirementまたはTarget Value Loopとの関係を更新
4. 関連原則へ接続
5. effectを更新
6. 矛盾検査
7. 影響を受ける下流成果物を `stale` にする
8. 正常系と例外系の未解決数を確認する
9. 次の質問を選ぶ

## 5. 疲労・ADHD配慮モード

兆候：

- 「疲れた」
- 「何からだっけ」
- 長い説明の途中で見失う
- 質問が多いと負担になる

応答を次へ縮退する。

```markdown
### 今ここ

| 項目 | 状態 |
|---|---|
| 直前ステージ | Decision Specification（S4） |
| 現在ステージ | Design Principles（S5） |
| 進捗 | 5/9 |

### 次の1問
初回理解と、2回目以降の速度は、別の画面状態として扱いますか？

**推奨：y** — 初回と反復利用では必要な情報量が異なるため。

`y` = 別状態、`n` = 同じ状態として答えてください。
```

必要になるまで他の説明は追加しない。直前ステージ、現在ステージ、`n/9`、推奨、理由、回答ガイドは省略しない。

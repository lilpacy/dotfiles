## 問題点

セットアップ説明に自ら書かれている通り、`revctl` は起動時に `~/.revctl/plugins/` を自動読み込みし、レビュー担当エンジニアのマシンには大体 `checklist-helper` プラグイン（今回比較しているチェックリストと同じ観点を出す）が入っています。

つまり `without_checklist` 条件は「プロンプトにチェックリストを埋め込まない」ようにしただけで、「実行環境全体でチェックリスト相当の観点が一切出ない」ことは何も保証していません。プロンプトを見ていない審査員（この場合はレビュー担当者のマシン上の `revctl`）が、プラグイン経由で結局同じ観点を出していた可能性があります。これが起きていると、`with_checklist` と `without_checklist` の差（90% vs 70%、80% vs 60%）は「チェックリスト機能の効果」ではなく「たまたまそのマシンに `checklist-helper` が入っていたかどうかの差」を測っていることになり、報告の因果クレームが崩れます。

## やるべき確認（本番集計の前に1回でいい）

1. **`without_checklist` が保証すべきことを一文で確認する**: 「チェックリストと同じ観点がプロンプト経由でも、プラグイン経由でも、レビュー結果に一切現れないこと」。プロンプトから抜いただけでは満たせません。
2. **`without_checklist` の実行ログを1件、生ログで確認する**（サマリではなく）。具体的には各レビュー担当者の実行時に `revctl` がロードしたプラグイン一覧、または出力そのものを `grep -i checklist-helper` してみてください。もし1件でもヒットしたら、その時点で「混入あり」が確定します。
3. 混入が見つかった場合、`without_checklist` の10件全部について、実行時に `checklist-helper` を無効化してから（例: 一時的に空の plugin dir を指す環境変数を渡す、`--no-plugins` 相当のフラグがあれば使う）再実行し、無効化できたことを同じ grep で確認してから再集計してください。
4. この確認をクリアするまでは、「チェックリスト機能には効果がある」という結論は保留し、報告するなら「未検証(n=10、プラグイン混入未確認)」と明記してください。

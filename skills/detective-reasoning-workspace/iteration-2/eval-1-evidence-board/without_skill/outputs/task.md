# 調査メモ: バッチ処理の間欠的な遅延

夜間バッチ`invoice-sync`が「たまにだけ」5分以上遅延する問題を数日追いかけている。今日の調査メモをそのまま貼るので、この内容を見て、この件はもう解決とみなして閉じてよいか、意見をもらいたい。

## 調査メモ（時系列）

**8/15（月）朝一の単発確認**
ステージング環境で1回だけ手動実行してみた。ジョブ内で外部APIを呼ぶ箇所があり、そこがタイムアウト設定なし（無限待ち）になっていた。念のため直しておいたが、この時点ではまだ本番の遅延と関係あるかは不明。念のため実行ログを見たが、遅延は再現しなかった（3分で完了）。

**8/17（水）本番で3回連続実行を観察**
遅延が起きた日の実行ログを3日分集めて並べた。3回とも「DB接続プールの待機」で数分固まっていた。プールサイズが5のままスケールしていないのが原因と判断し、プールサイズを20に増やした。

**8/18（木）プールサイズ変更後、2回観察**
プールサイズを増やした後の実行を2回見た。どちらも遅延なし（3分台で完了）。「直った」と判断してよさそうに見えた。

**8/19（金）念のためもう3回観察**
安心して見ていたら、金曜の実行で再び遅延（7分）が発生。ログを見ると、今度は「DB接続プールの待機」ではなく「外部APIレスポンス待ち」で固まっていた。金曜だけ外部API側が一時的に重かったのだろうと考え、監視ダッシュボードで外部APIのレスポンスタイム分布を確認したところ、金曜のその時間帯だけ p99 が跳ねていたのを確認できた。「外部API側の一時的な遅さが原因」と結論し、今日はこの件を一旦クローズしようと思っている。

この結論で問題ないか、それとも何か引っかかる点はあるか？

# ログ追加完了

## 対応内容

sync_worker.py に本番切り分けに必要な詳細ログを追加しました。

### 追加した内容

1. **ファイルロギング** → `/var/log/sync_worker.log` に DEBUG レベルで記録（cron の stdout/stderr 破棄に対応）

2. **各ステージの入出力をキャプチャ**
   - fetch_orders: リクエスト cursor、受信バイト数、取得行数、next_cursor
   - transform: order_id、計算結果（total、region）、データ構造エラー時は注文全体
   - upload: row_id、ステータス

3. **エラー時の十分な文脈**
   - JSON デコード失敗 → 受信本体の先頭 500 バイト
   - 必須フィールド欠損 → 対象 order/row 全体の先頭 500 バイト
   - 全例外で stack trace (`exc_info=True`)

4. **進捗追跡**
   - sync 開始・完了ログ
   - ページ処理ごとの順序と失敗時の進捗状況（synced count、cursor）

## 検出可能な故障

このログ設定で今夜の 2:00 実行時に失敗した場合、以下が判定できます：
- 失敗箇所：API 呼び出し段階、データ変換段階、アップロード段階
- 失敗の原因：ネットワークエラー、JSON 形式エラー、必須フィールド欠損、型エラー
- 失敗時の状態：処理済み行数、失敗したリソース ID、問題のあるデータ構造

再デプロイなしにログから原因特定でき、2 回目の実行で修正を検証できます。

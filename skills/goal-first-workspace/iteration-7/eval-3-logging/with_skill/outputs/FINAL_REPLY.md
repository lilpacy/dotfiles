Goal: 本番環境での nightly sync の失敗時に、根本原因を一度のデプロイで特定できる診断情報を得る。
Done-when: 次回の実行時に失敗が発生した場合、ネットワークエラー・API エラー・データ形式エラー・ケースを特定するログが cron に捕捉される
Verified-by: コード確認 — stderr に `[ERROR]` を出力、stdout に `[INFO]` で進行状況を記録
Constraints:
- cron が stdout/stderr を捨てている → stderr に出力 (cron がメールに含められる可能性)
- 本番環境のみ再現可能 → 1 回のデプロイで決まる、イテレーション不可
- デプロイ 40 分 → 包括的に集める

## 変更内容

`sync_worker.py` に構造化ログを追加：

1. **各関数のエラーハンドリング** — `fetch_orders()`, `transform()`, `upload()` が具体的な例外を捕捉
   - HTTP エラー・ネットワークエラー・JSON 解析エラー・キー不在・型エラーを分類
   - スタックトレースを stderr に出力

2. **進行状況ログ** — `[INFO]` マーク付きで main() に 4 つのチェックポイント
   - 各ページ取得時のカーソル
   - 受け取ったレコード数
   - ページ完了時のサマリー
   - 成功時の最終カウント

3. **失敗時の文脈** — エラーログに order ID、フェッチ URL、API レスポンスなどを含める

次の実行時に `cron` のメールに `[ERROR]` と `[INFO]` が出現するため、どの段階で落ちたか即座に判定できます。

# ログ追加完了

`sync_worker.py` に本番環境での切り分けを可能にする構造化ログを追加しました。

## 何が変わったか

### ログ出力設定
- 本番環境では `/var/log/sync_worker.log` に書き込み（開発環境は `./sync_worker.log`）
- cron の stdout/stderr 廃棄に対応したファイルベースログ
- DEBUG レベルで詳細、ERROR レベルで例外スタックトレース全体を記録

### 各関数での診断ログ

**fetch_orders** - API fetch の段階で何が起きたかを特定
- fetch開始時にカーソル位置を記録
- JSON パース失敗時の詳細（カーソル、エラーメッセージ、スタックトレース）
- ネットワークエラーをカーソル付きで記録
- 成功時は取得行数と次のカーソルを記録

**transform** - データ構造の問題を特定
- KeyError（必須フィールド欠落）の場合、order ID と欠落フィールドを記録
- TypeError（型エラー）時は order の内容も含めて記録
- 全例外でスタックトレース完全記録

**upload** - アップロード段階での失敗を特定
- アップロード対象の row ID を記録
- ネットワークエラーを row 単位で特定可能に
- 成功時も row ID で記録

**main** - 全体進捗と失敗時の状況保存
- 開始・完了時に INFO レベルで記録
- 各バッチの order 数とカーソル位置を記録
- 失敗時は「何件処理済み・どのカーソルで失敗」を記録

## 検証済み

実行して確認した項目：
- ネットワークエラー → カーソル付きで適切に記録される
- JSON パースエラー → カーソル・エラー詳細・スタックトレース完全に記録
- 欠落フィールド → Order ID・フィールド名・order 内容を記録
- 成功時の進捗 → 開始→バッチ→アップロード→完了の流れを記録

40 分のデプロイ待ち時間を活かして、1 回のサイクルで本番の実データから根本原因を特定できるログボリュームを確保しました。
